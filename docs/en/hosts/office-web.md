# PowerPoint web add-in (Office.js)

> German: [../../de/hosts/office-web.md](../../de/hosts/office-web.md)

## Architecture

- **Engine:** the C# engine (`src/InventaSketch.Engine` + modules) compiled to .NET WebAssembly by
  `hosts/office-web/engine/InventaSketch.Web.Engine.csproj` (`Microsoft.NET.Sdk.WebAssembly`, no workload needed).
  TypeScript calls it through `[JSExport]` methods with JSON strings (`src/engine/*`). Size: about 2.1 MB Brotli;
  start in the browser about 0.5 s (warm) to 5 s (cold, measured 2026-11-20 in the dev build).
- **UI (TypeScript, Vite):** library with search (EN/DE), categories and favourites; stage with selection handles,
  snapping guides, insert at pointer, pie menu (right-click / `Shift+F10`), floating context bar, inspector;
  light/dark/auto theme; German/English auto detection (`src/ui/*`, `src/theme.ts`, `src/i18n.ts`).
- **Office adapter:** `src/office/*` translates engine draw plans into PowerPoint shapes (capability-aware), serialises
  all `PowerPoint.run` calls through a work queue and stores ids/model in shape tags.
- **Manifest:** generated by `scripts/manifest.mjs` (base URL argument or `ISK_BASE_URL`), with `EquivalentAddins`
  naming the COM add-in `InventaSketch.AddIn.Connect` so Windows hides the web add-in while the COM add-in is installed.

## Engine API

All calls go through `EngineExports.Call(method, json)` and return `{"ok":true,"result":…}` or
`{"ok":false,"error":"…"}` (`src/InventaSketch.Engine/EngineApi.cs`, request bag `Contracts.cs`, typed client
`src/engine/client.ts`). Requests are camelCase JSON; geometry in mm (draw plans and host rectangles in pt). Every
editing method takes `session`; `ids` defaults to the current selection. Mutations return the editor state and are one
undo step each (no step when nothing changes).

Editor state: `session`, `revision`, `pageId`, `pageWidth`, `pageHeight`, `grid`, `selection`, `selectionBounds`,
`canUndo`, `canRedo`, `undoLabel`, `objects`, `svg` (page SVG, black and white when the document is), `planScale`,
`monochrome`, `changed` (objects added or modified by the change that produced this revision, also by undo/redo; every
object after `setMonochrome`, every plan-scale object after `setPlanScale`) and `dependents` (further objects whose
rendering depends on the changed or removed ones: wall joints, openings). Hosts redraw the units of `changed` plus
`dependents` in one step. Each object carries id, type, name, kind (box/points), bounds, centre, size, rotation, flips,
points, group, view, text and reference; **selected** objects also carry `centred` (pitch circle or hub anchor: resize
about the centre by default) and `mainText` `{ key, label, value }`: the numeral of reference numerals and lead lines,
else the object text of text types, else the first text parameter among text, label, name and title (`key` absent for
the object text). `importCompact` adopts the slide model's black-and-white setting, so live redraws keep the look of
the units on the slide.

## Editing UX (parity with the COM add-in, 2026-11-20)

- **Pie menu** (right-click, `Shift+F10`, "…" in the bar): a ring of sectors with a pictogram over each label, at most
  eight entries; delete, views (up to four), "Text …", "Insert …", duplicate and rotate first, type actions, numeral,
  mirror, order and grouping behind "More ▸" (paged with Back). Labels wrap at spaces only (two lines, smaller font
  before shortening with "…"); the full label of a shortened or unavailable entry appears in a pill below the ring.
  Layout and wrapping are pure functions in `src/ui/pielogic.ts` (unit-tested).
- **Text**: double-click on an object, the text button in the context bar or "Text …" in the pie menu edit the main text
  (`mainText`, `setMainText`) in the inline prompt; multi-line texts open the inspector's text box.
- **Insert …** in the pie menu opens the insert box (see the UI/UX round below); the chosen item starts insert at the
  pointer on the stage (with snapping). In the COM add-in's sidebar it sends the existing `place` bridge message, so the
  element is placed on the slide.
- **Black and white**: toggle in the top bar (and in Settings) calls `setMonochrome`; the stage, SVG/PNG export and the
  draw plans written by `src/office/powerpoint.ts` (or the COM bridge) follow the document setting. Clicking again
  restores the colours; undo works.
- **Line weights** (2026-11-25): a choice next to it calls `setLineGroup` (ISO 128 line group, 0.5 mm standard); like
  black and white it is a document setting that a slide model brings into the page session (`importCompact`), so live
  sync redraws every unit with it. Checked in the browser dev page (strokes doubled at 1 mm).
- **Accent colour** (2026-11-25): a third choice calls `setAccent` (presets from `accents`); checked in the browser dev
  page (a battery's green charge became red, its blue-grey housing stayed).
- **Resize**: centred parts (gears, bearings, wheels: `centred`) scale about their centre by default, Ctrl from the
  opposite edge; other objects the other way round. A label next to the pointer shows the size (or factor) and the
  active mode with its Ctrl alternative.
- **Choices as dropdowns** (like the COM add-in): the context bar shows every choice of the selected element as a
  button with the current value (pictogram from the option icons, else short text) and a caret; a click opens a list with
  icon and label per option (`inspector` params with `options[].icon`, `mirrorIcons`; line type via `conversions`, line
  style via `setStyle`). Type actions whose `paramKeys` are shown as choices are left out.
- **Quick add** (like the COM add-in): a selected flowchart, UML, ER, BPMN or basic element (`chain`) shows blue
  triangles outside its sides; click adds a connected copy (`quickAdd`), drag and drop adds it at the drop point. The
  context bar then starts with "Make it …", which opens the insert box with what the new element can become
  (`nextItems`, typing searches the library; the pick calls `replaceItem`). No thumbnail row is appended to the bar.
- **Coupling:** moves, resizes and parameter edits keep gears in mesh and gears on their shafts (engine `Coupling`);
  holding Alt while releasing edits freely (`couple: false`, `Session.couple`).
- **Anchor** (settings, on by default, like the COM add-in's ribbon toggle): a line end dragged onto a snap target
  attaches to it and follows when the target moves. Off: the end still snaps but stays where it is.
- **Pie menu "Label ▸"** for lines, arrows, dimensions and lead lines: entries generated from the type parameters
  (text prompts, switches, choices, text size), like the COM add-in.

## UI/UX round 2026-11-24 (parity with the COM add-in)

Follows the binding UX rules in the roadmap ("Plan 2026-11-24"). Pure rules in `src/ui/uxlogic.ts` and
`src/ui/insertbox.ts`, unit-tested in `test/uxround.test.ts`.

- **Context-only bar, fixed order:** "Make it …" (right after a quick add) | views | choices | text, numeral, up to three
  type actions | insert, draw the path, select assembly | mirror/rotate | style, more. Mirror and rotate appear only when
  `transformEffect` says they change the drawing (a circle or a gear in axial view shows none of them); the pie menu
  follows the same rule. Pictograms with bilingual tooltips; the bar never grows with content.
- **One insert flow:** the insert button in the bar, "Insert …" in the pie menu and Ctrl+Space (also without a
  selection) open the insert box at the pointer. Without typing it lists the parts that fit the selection first
  (marked "fits"/"passt") and then the recent items; typing searches the whole library (`search`). ↑/↓ move, Enter
  takes the marked row, Esc or a click elsewhere closes. Rows show the library thumbnails. The chosen item follows the
  pointer with snapping (click places it, Esc cancels). Recent items (last 12) are kept in the per-user settings
  (localStorage); library inserts count too.
- **Multi-selection bar:** with two or more elements selected (a group counts as one), the bar shows the operations of
  `arrangeOptions` as icons with tooltips – one view for all (the mechanism kept), centres on a row or column, even
  spacing, like the first, renumber reference numerals – each only when it changes something; a click runs `arrange`
  (one undo step). Style and the pie menu stay available.
- **Select assembly:** shown when the selection is coupled with parts that are not selected yet (`assembly`); a click
  selects all coupled objects, which then get the multi-selection bar.
- **Snap labels:** while dragging, the label from `snapMove` ("axis", "pitch circle", "pin 2") is shown next to the
  snap target (docking point, snapped circle or segment).
- **Draw the path:** a link of a self-built linkage with F = 1 (`trace` returns a path) offers "Draw the path"; it
  inserts the coupler curve of the link's end as a motion path (`kin.path`, or `kin.path.closed` for a closed curve;
  an open path without arrowhead), one undo step (`drawTrace`).
- **Motion mode:** see "Motion mode" below (since 2026-11-25; before that COM-only).

## Remaining COM features (2026-11-24)

Pure rules in `src/ui/buildlogic.ts`, unit-tested in `test/buildlogic.test.ts`.

- **Build "+" on ports:** a single selected gear, ring gear, shaft, e-machine, engine or link shows a blue "+" at every
  free build port (`buildPorts`): 15 px beyond the port along its outward direction with a thin dashed lead line,
  pushed further out until it is clear of the resize and rotate handles; a free hub's "+" sits beyond the top right
  corner, so the element can still be dragged by its centre (same as the COM add-in). The tooltip names what docks
  there. The context bar keeps clear of the "+" and the rotate handle. A click opens the insert box at the "+" with the
  parts that dock there (`buildItems`, marked "fits"); choosing one docks it, coupled and selected (`buildPlace`, one
  undo step). Typing searches the whole library; anything that does not dock there starts the normal placement at the
  pointer.
- **Stretch a shaft end:** dragging the "+" at a shaft end (`stretch`) previews the new end on the shaft axis (pointer
  snapped, then projected onto the axis) with the change in length next to the pointer; on release `buildStretch`
  lengthens or shortens the shaft without coupling, so the parts on it keep their place (one undo step).
- **Live coupling preview:** while dragging or resizing the selection, the neighbours the coupling will move or scale
  on release (meshing gears, parts on a shaft) are drawn in blue (`couplingPreview` with `dx`/`dy`, or `sx`/`sy` about
  the resize pivot), throttled to about 15 updates per second with a trailing update for the last position. Release,
  Esc or Alt (free edit) clears it. Rotations have no preview.
- **Ghost positions:** a link of a self-built linkage with F = 1 (`dof`, or a traced path) gets a bar button (icon
  `cmd-animate`) that inserts four dashed grey copies of the chain over the crank's range as one group (`drawGhosts`,
  one undo step).
- **Dimension between two parts:** with exactly two parts selected, the multi-selection bar shows "Dimension between
  the two (centre distance)" from `arrangeOptions` (`dim`, icon `cmd-dimension`, label from the engine); a click inserts
  an aligned dimension docked on both axes (one undo step).

Checked in the browser (dev.html, 2026-11-24): five "+" on a spur gear (four meshing, one hub), a meshing gear docked
from the right "+"; a shaft lengthened from 120 to 155 mm and shortened by a real mouse drag with the gear on it kept in
place; a bearing docked at the shaft end; a typed search item started the normal placement; the blue preview of the
meshing gear while dragging and while resizing its partner, cleared on release, matching the result; twelve ghost
links inserted as one group; a 70.7 mm centre distance dimension between two gears.

### Library search (2026-11-25)

The sidebar library ranks typed queries with the engine's `search` (both languages, umlauts = ae/oe/ue/ss, recent
items first, names starting with the query before keyword hits) like the insert box; the category chips and favourites
still filter (`rankedItems` in `src/ui/library.ts`).

## Build and run

npm ci

## Install for users (no administrator rights)

`scripts\package-web.ps1` builds `dist\InventaSketch-Web` (and a ZIP): `App\` (task pane + WebAssembly engine),
`Server\InventaSketch.WebHost.exe`, `manifest.xml` for `https://localhost:3217/` (Slidemax-Web uses 3000) and the
install scripts with `README.md` / `README.de.md`. The local host and scripts were ported from Slidemax with the
copyright holder's approval and translated to English; console output, message texts and help are German if the user's
language is German (Windows UI language, or `LC_ALL`/`LC_MESSAGES`/`LANG` on macOS/Linux), otherwise English.

- **Windows:** close PowerPoint, double-click `Install web add-in.cmd`, confirm Windows' certificate prompt once.
  It copies to `%LOCALAPPDATA%\InventaSketch\Web`, creates and trusts a `localhost` certificate in the user store, adds
  an autostart entry, starts the loopback-only HTTPS host and registers the manifest for sideloading
  (`HKCU\Software\Microsoft\Office\16.0\WEF\Developer`). Options: `--no-autostart`, `--no-manifest`, `--dry-run`
  (the German names `-OhneAutostart`, `-OhneManifest`, `-Probelauf` remain accepted). Uninstall:
  `Uninstall web add-in.cmd`; start/stop without reinstalling: `Start web add-in.cmd`, `Stop web add-in.cmd`.
  `Server\InventaSketch.WebHost.exe --help` lists all options. While the COM add-in is installed, Office hides the web
  add-in.
- **macOS:** `install.command` (Python 3): copies to `~/Library/Application Support/InventaSketch/Web`, trusts the
  certificate in the keychain, LaunchAgent, manifest in PowerPoint's `wef` folder. Uninstall: `uninstall.command`.
- **Linux / PowerPoint on the web:** `sh install.sh`, then upload `manifest.xml` via *Add-ins › My add-ins ›
  Upload my add-in*. Uninstall: `sh uninstall.sh`; `start.sh` / `stop.sh` control the server. Options of
  `inventasketch_web.py`: `--no-autostart`, `--dry-run` (German aliases `--ohne-autostart`, `--probelauf`).
- **Own HTTPS server (IT):** `create-manifest.ps1 -Address https://...` or `sh create-manifest.sh https://...` writes
  `manifest-<host>.xml` for the folder `App` hosted elsewhere.

Verified 2026-11-20 on Windows: package build, dry run of the installer (plan incl. COM detection), host with a
temporary in-memory certificate served `taskpane.html` and the engine over HTTPS, rejected `../` traversal, status and
stop worked; Linux dry run of the Python installer. Not yet done: a real install with certificate trust (needs the
user's confirmation), macOS run, loading the add-in in PowerPoint. After the translation (2026-11-20): host build
without warnings, package build, installer dry runs in English and German (new option names and German aliases), HTTPS
smoke test (200, `../` 404, foreign Host 400, POST 405), Python dry runs (Linux, simulated macOS) in both languages.

## Motion mode (2026-11-25)

Like the COM add-in ("Moving gear trains live by dragging in motion mode", linkage dragging): dragging moves things only
the way they can move. Pure rules in `src/ui/motionlogic.ts`, unit-tested in `test/motionlogic.test.ts`.

- **Toggle:** the bar shows "Move: drag turns the gears / linkage" (icon `cmd-motion`, a toggle button with
  `aria-pressed`) between the build commands and "Explode" when `motionInfo` says `linkage`, or `gear` with `coupled`
  true. A lone gear coupled with nothing only spins in place, which shows nothing, so it gets no button (same rule as
  COM). The state is session only, like COM: it is not saved and the task pane always starts in edit mode. Switching it
  on shows a short hint in the status line.
- **Handles in motion mode:** a selected part that can move shows only what moves it: a gear its dashed frame and a
  cross at its centre, a link its joints (filled blue). Resize, rotate, quick-add and build "+" handles are hidden, so
  every drag on it is a motion. Parts that cannot move keep their usual handles and drag as usual.
- **Turning a gear:** dragging anywhere on the selected gear's frame (or on any coupled gear, which gets selected) turns
  it about its centre (`x`/`y` from `motionInfo`) by the angle the pointer sweeps around it, accumulated across ±180° and
  full circles (clockwise on screen positive); Shift turns in 15° steps. The angle is shown at the centre with a dashed
  lever to the pointer.
- **Dragging a link:** dragging a joint handle of the selected link pulls that joint; dragging elsewhere on a link pulls
  its nearest joint. The pulled point and a dashed line from its start are shown.
- **Preview and release:** during the drag the engine's `motionPreview` (the turned train or the moved chain) is drawn
  in the ghost layer at about 15 updates per second (same throttle as the coupling preview, trailing update for the last
  position) and the current drawing of the moved objects is dimmed; the context bar hides once the drag moves. Release
  applies `motionTurn` or `motionDrag` once (one undo step: "Turn" / "Move linkage"); a click without a drag changes
  nothing; Esc cancels and restores the bar. With motion mode off dragging edits as before.

Checked in the browser (dev.html, 2026-11-25): a spur gear with a meshing gear docked from its build "+": the motion
button appears (not for a lone gear), a real mouse drag over a quarter circle turned the gear by +90.4° and its mate
from -10° to -100.4° with both centres unchanged, one undo step "Turn"; with motion mode off the same drag moved the
gear. An exploded `kin.fourbar` (F = 1): dragging the crank's joint by 30° about its pivot kept all link lengths
(9.124 / 27.371 / 22.809 mm) with the pivots in place, one undo step "Move linkage"; the preview showed the moved crank
and coupler with their originals dimmed; a drag started on the coupler with nothing selected selected it, and Esc
cancelled it without a change. Known gap (engine): `motionPreview` leaves out a link that only moves through a docked
joint (the rocker of the four-bar), and every preview solves from the document state rather than from the last
preview, so a long drag of a linkage may jump to the other assembly mode in the preview (the COM add-in solves from
the last position).

## Webspace package

`dist/InventaSketch-Webspace` (and `dist/InventaSketch-Webspace-<version>.zip`, which contains the folder) offers the web
add-in from any HTTPS webspace, without a server on the user's computer. Build it with `scripts/package-webspace.ps1`
(Windows) or `scripts/package-webspace.sh` (Linux/macOS); `scripts/build.ps1` and `scripts/build.sh` run it after the web
and COM packages and only warn if the web build is missing. The work is done by `hosts/office-web/webspace/package.mjs`
(`npm run webspace`).

Contents:

- the built web add-in (`hosts/office-web/dist` without `dev.html`, source maps and the localhost manifest), including the
  precompressed engine files (`_framework/*.br`, `*.gz`);
- `index.html` with `setup.js`: the setup page. It takes the folder of its own address (`location`, without file name,
  query and fragment) as the add-in address, checks it with the rules of `create-manifest.ps1` (HTTPS only, no query or
  special characters), shows it and offers the manifest as `manifest-<host>[-<port>].xml` on a button. It also explains
  "Upload My Add-in" for PowerPoint on Windows, Mac and the web, the Mac `wef` folder and the Windows registry
  (`HKCU\Software\Microsoft\Office\16.0\WEF\Developer`) with copyable commands for when the upload is missing, the shared
  folder catalog and central deployment by IT. Texts are German if the browser language starts with `de`, otherwise
  English; a button switches the language;
- `manifest-template.js`, generated from `scripts/manifest.mjs` (`manifestTemplateModule`): the manifest template and
  `fillManifest`, so the page and `node scripts/manifest.mjs <url>` produce the same XML for the same address
  (`test/webspace.test.ts`);
- `.htaccess` (Apache) and `web.config` (IIS): MIME types for `.wasm`, `.dll`, `.dat`, `.blat`, `.json`, `.js`, `.br`,
  `.gz`; no directory listing; `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, `Cache-Control: no-cache` (a new
  upload arrives at once); crawlers, preview services and tools are rejected by user agent. Apache serves the `.br`/`.gz`
  copies with `Content-Encoding` when the browser accepts them (needs `mod_rewrite` and `mod_headers`, otherwise the
  originals are served). IIS serves the originals and compresses itself; precompressed files would need the optional URL
  Rewrite module, whose absence breaks the whole folder;
- `robots.txt` (`Disallow: /`; crawlers only read it at the root of a host, in a subfolder the header and the robots meta
  tag apply);
- `version.json` (version line on the page) and `downloads.json` with `downloads/`: the other editions found next to the
  package in `dist`: `InventaSketch-AddIn-<version>.zip` (COM add-in) and `InventaSketch-LibreOffice-<version>[-<rid>].oxt`.
  Only existing files are listed, never expected ones; without them the page says that there are no other editions.

Use: upload the folder with all files (FTP programs show `.htaccess` only with hidden files enabled) to a folder with a
name that cannot be guessed, e.g. `https://example.com/isk-7k2q9x/`. Requirements: HTTPS with a valid certificate and no
password protection (Office add-ins cannot sign in). Open the address in the browser, download the manifest and upload it
in PowerPoint (Home > Add-ins > More Add-ins > My Add-ins > Upload My Add-in). Presentation data is not sent to the
webspace. Updates: upload the new folder and replace the old content; a new manifest is only needed when the manifest
changed.
