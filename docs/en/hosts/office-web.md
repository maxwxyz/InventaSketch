# PowerPoint web add-in (Office.js)

> German: [../../de/hosts/office-web.md](../../de/hosts/office-web.md)

## Architecture

- **Engine:** the C# engine (`src/InventaSketch.Engine` + modules) compiled to .NET WebAssembly by
  `hosts/office-web/engine/InventaSketch.Web.Engine.csproj` (`Microsoft.NET.Sdk.WebAssembly`, no workload needed).
  TypeScript calls it through `[JSExport]` methods with JSON strings (`src/engine/*`). Size: about 2.1 MB Brotli;
  start in the browser about 0.5 s (warm) to 5 s (cold, measured 2026-11-20 in the dev build).
- **UI (TypeScript, Vite):** library with search (EN/DE), categories and favourites; stage with selection handles,
  snapping guides, insert at pointer, pie menu (right-click / `Shift+F10`), floating context bar, inspector;
  light/dark/auto theme; German/English auto detection (`src/ui/*`, `src/theme.ts`, `src/i18n.ts`).
- **Office adapter:** `src/office/*` translates engine draw plans into PowerPoint shapes (capability-aware), serialises
  all `PowerPoint.run` calls through a work queue and stores ids/model in shape tags.
- **Manifest:** generated by `scripts/manifest.mjs` (base URL argument or `ISK_BASE_URL`), with `EquivalentAddins`
  naming the COM add-in `InventaSketch.AddIn.Connect` so Windows hides the web add-in while the COM add-in is installed.

## Build and run

```powershell
cd hosts/office-web
npm ci
npm test            # vitest (manifest, library filter)
npm run build       # engine publish + icons + typecheck + vite build + manifest -> dist/
npm run dev         # dev server on port 3000 (https if office-addin-dev-certs are installed)
```

`dev.html` runs the same app without Office (engine in WebAssembly, slide commands hidden) for UI work in any browser.

## Install for users (no administrator rights)

`scripts\package-web.ps1` builds `dist\InventaSketch-Web` (and a ZIP): `App\` (task pane + WebAssembly engine),
`Server\InventaSketch.WebHost.exe`, `manifest.xml` for `https://localhost:3217/` (Slidemax-Web uses 3000) and the
install scripts with `README.md` / `README.de.md`. The local host and scripts were ported from Slidemax with the
copyright holder's approval and translated to English; console output, message texts and help are German if the user's
language is German (Windows UI language, or `LC_ALL`/`LC_MESSAGES`/`LANG` on macOS/Linux), otherwise English.

- **Windows:** close PowerPoint, double-click `Install web add-in.cmd`, confirm Windows' certificate prompt once.
  It copies to `%LOCALAPPDATA%\InventaSketch\Web`, creates and trusts a `localhost` certificate in the user store, adds
  an autostart entry, starts the loopback-only HTTPS host and registers the manifest for sideloading
  (`HKCU\Software\Microsoft\Office\16.0\WEF\Developer`). Options: `--no-autostart`, `--no-manifest`, `--dry-run`
  (the German names `-OhneAutostart`, `-OhneManifest`, `-Probelauf` remain accepted). Uninstall:
  `Uninstall web add-in.cmd`; start/stop without reinstalling: `Start web add-in.cmd`, `Stop web add-in.cmd`.
  `Server\InventaSketch.WebHost.exe --help` lists all options. While the COM add-in is installed, Office hides the web
  add-in.
- **macOS:** `install.command` (Python 3): copies to `~/Library/Application Support/InventaSketch/Web`, trusts the
  certificate in the keychain, LaunchAgent, manifest in PowerPoint's `wef` folder. Uninstall: `uninstall.command`.
- **Linux / PowerPoint on the web:** `sh install.sh`, then upload `manifest.xml` via *Add-ins › My add-ins ›
  Upload my add-in*. Uninstall: `sh uninstall.sh`; `start.sh` / `stop.sh` control the server. Options of
  `inventasketch_web.py`: `--no-autostart`, `--dry-run` (German aliases `--ohne-autostart`, `--probelauf`).
- **Own HTTPS server (IT):** `create-manifest.ps1 -Address https://...` or `sh create-manifest.sh https://...` writes
  `manifest-<host>.xml` for the folder `App` hosted elsewhere.

Verified 2026-11-20 on Windows: package build, dry run of the installer (plan incl. COM detection), host with a
temporary in-memory certificate served `taskpane.html` and the engine over HTTPS, rejected `../` traversal, status and
stop worked; Linux dry run of the Python installer. Not yet done: a real install with certificate trust (needs the
user's confirmation), macOS run, loading the add-in in PowerPoint. After the translation (2026-11-20): host build
without warnings, package build, installer dry runs in English and German (new option names and German aliases), HTTPS
smoke test (200, `../` 404, foreign Host 400, POST 405), Python dry runs (Linux, simulated macOS) in both languages.

## Sideloading (development)

Windows: `npm run certs` once (trusted localhost certificate), `npm run dev`, then add the manifest path as a value under
`HKCU\Software\Microsoft\Office\16.0\WEF\Developer` (name = add-in id) and restart PowerPoint.
For end users, use the local installer described above.

## Webspace package

`dist/InventaSketch-Webspace` (and `dist/InventaSketch-Webspace-<version>.zip`, which contains the folder) offers the web
add-in from any HTTPS webspace, without a server on the user's computer. Build it with `scripts/package-webspace.ps1`
(Windows) or `scripts/package-webspace.sh` (Linux/macOS); `scripts/build.ps1` and `scripts/build.sh` run it after the web
and COM packages and only warn if the web build is missing. The work is done by `hosts/office-web/webspace/package.mjs`
(`npm run webspace`).

Contents:

- the built web add-in (`hosts/office-web/dist` without `dev.html`, source maps and the localhost manifest), including the
  precompressed engine files (`_framework/*.br`, `*.gz`);
- `index.html` with `setup.js`: the setup page. It takes the folder of its own address (`location`, without file name,
  query and fragment) as the add-in address, checks it with the rules of `create-manifest.ps1` (HTTPS only, no query or
  special characters), shows it and offers the manifest as `manifest-<host>[-<port>].xml` on a button. It also explains
  "Upload My Add-in" for PowerPoint on Windows, Mac and the web, the Mac `wef` folder and the Windows registry
  (`HKCU\Software\Microsoft\Office\16.0\WEF\Developer`) with copyable commands for when the upload is missing, the shared
  folder catalog and central deployment by IT. Texts are German if the browser language starts with `de`, otherwise
  English; a button switches the language;
- `manifest-template.js`, generated from `scripts/manifest.mjs` (`manifestTemplateModule`): the manifest template and
  `fillManifest`, so the page and `node scripts/manifest.mjs <url>` produce the same XML for the same address
  (`test/webspace.test.ts`);
- `.htaccess` (Apache) and `web.config` (IIS): MIME types for `.wasm`, `.dll`, `.dat`, `.blat`, `.json`, `.js`, `.br`,
  `.gz`; no directory listing; `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, `Cache-Control: no-cache` (a new
  upload arrives at once); crawlers, preview services and tools are rejected by user agent. Apache serves the `.br`/`.gz`
  copies with `Content-Encoding` when the browser accepts them (needs `mod_rewrite` and `mod_headers`, otherwise the
  originals are served). IIS serves the originals and compresses itself; precompressed files would need the optional URL
  Rewrite module, whose absence breaks the whole folder;
- `robots.txt` (`Disallow: /`; crawlers only read it at the root of a host, in a subfolder the header and the robots meta
  tag apply);
- `version.json` (version line on the page) and `downloads.json` with `downloads/`: the other editions found next to the
  package in `dist`: `InventaSketch-AddIn-<version>.zip` (COM add-in) and `InventaSketch-LibreOffice-<version>[-<rid>].oxt`.
  Only existing files are listed, never expected ones; without them the page says that there are no other editions.

Use: upload the folder with all files (FTP programs show `.htaccess` only with hidden files enabled) to a folder with a
name that cannot be guessed, e.g. `https://example.com/isk-7k2q9x/`. Requirements: HTTPS with a valid certificate and no
password protection (Office add-ins cannot sign in). Open the address in the browser, download the manifest and upload it
in PowerPoint (Home > Add-ins > More Add-ins > My Add-ins > Upload My Add-in). Presentation data is not sent to the
webspace. Updates: upload the new folder and replace the old content; a new manifest is only needed when the manifest
changed.

Origin: setup page, server settings and packaging were ported from Slidemax-Webspace (same copyright holder) and
translated to English.

Verified 2026-11-20 on Windows: package build (111 files, COM add-in ZIP listed); the folder served by a local static
server in a subfolder over HTTPS (temporary self-signed certificate) and HTTP; the page loaded in headless Edge in German
and English: address `https://localhost:<port>/isk-test`, generated manifest well-formed XML with this address and
identical to `scripts/manifest.mjs`; over HTTP the page refuses the address and disables the button. Not yet verified:
`.htaccess` on a real Apache and `web.config` on IIS, loading the add-in in PowerPoint from a webspace.
