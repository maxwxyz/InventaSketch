# PowerPoint web add-in (Office.js)

> German: [../../de/hosts/office-web.md](../../de/hosts/office-web.md)

## Architecture

- **Engine:** the C# engine (`src/InventaSketch.Engine` + modules) compiled to .NET WebAssembly by
  `hosts/office-web/engine/InventaSketch.Web.Engine.csproj` (`Microsoft.NET.Sdk.WebAssembly`, no workload needed).
  TypeScript calls it through `[JSExport]` methods with JSON strings (`src/engine/*`). Size: about 2.1 MB Brotli;
  start in the browser about 0.5 s (warm) to 5 s (cold, measured 2026-11-20 in the dev build).
- **UI (TypeScript, Vite):** library with search (EN/DE), categories and favourites; stage with selection handles,
  snapping guides, insert at pointer, pie menu (right-click / `Shift+F10`), floating context bar, inspector;
  light/dark/auto theme; German/English auto detection (`src/ui/*`, `src/theme.ts`, `src/i18n.ts`).
- **Office adapter:** `src/office/*` translates engine draw plans into PowerPoint shapes (capability-aware), serialises
  all `PowerPoint.run` calls through a work queue and stores ids/model in shape tags.
- **Manifest:** generated by `scripts/manifest.mjs` (base URL argument or `ISK_BASE_URL`), with `EquivalentAddins`
  naming the COM add-in `InventaSketch.AddIn.Connect` so Windows hides the web add-in while the COM add-in is installed.

## Engine API

All calls go through `EngineExports.Call(method, json)` and return `{"ok":true,"result":…}` or
`{"ok":false,"error":"…"}` (`src/InventaSketch.Engine/EngineApi.cs`, request bag `Contracts.cs`, typed client
`src/engine/client.ts`). Requests are camelCase JSON; geometry in mm (draw plans and host rectangles in pt). Every
editing method takes `session`; `ids` defaults to the current selection. Mutations return the editor state and are one
undo step each (no step when nothing changes).

## Editing UX (parity with the COM add-in, 2026-11-20)

- **Pie menu** (right-click, `Shift+F10`, "⋯" in the bar): since 2026-11-25 the eight fixed places of the interaction
  concept, see "Interaction concept" below (the earlier priority ring with "More ▸" is gone).
- **Text**: double-click on an object, the text button in the context bar or "Text …" in the pie menu edit the main text
  (`mainText`, `setMainText`) in the inline prompt; multi-line texts open the inspector's text box.
- **Insert …** in the pie menu opens the insert box (see the UI/UX round below); the chosen item starts insert at the
  pointer on the stage (with snapping). In the COM add-in's sidebar it sends the existing `place` bridge message, so the
  element is placed on the slide.
- **Black and white**: toggle in the top bar (and in Settings) calls `setMonochrome`; the stage, SVG/PNG export and the
  draw plans written by `src/office/powerpoint.ts` (or the COM bridge) follow the document setting. Clicking again
  restores the colours; undo works.
- **Line weights** (2026-11-25): a choice next to it calls `setLineGroup` (ISO 128 line group, 0.5 mm standard); like
  black and white it is a document setting that a slide model brings into the page session (`importCompact`), so live
  sync redraws every unit with it. Checked in the browser dev page (strokes doubled at 1 mm).
- **Accent colour** (2026-11-25): a third choice calls `setAccent` (presets from `accents`); checked in the browser dev
  page (a battery's green charge became red, its blue-grey housing stayed).
- **Compatibility check** (2026-11-25): a button in the top bar opens the "Compatibility" panel with the office
  (`patentProfiles`) and the preflight findings of the page (`preflight`) – errors first, then warnings, points to check
  by hand and notes, each with suggestion and the cited sources as short links; clicking a finding's message selects its
  element. The disclaimer is always shown. Checked in the browser dev page (light and dark, DPMA/EPO/PCT/USPTO switch, a
  gear outside the usable area selected from its finding). In PowerPoint (PowerPointApi 1.3) the panel offers **All
  slides**: the units of every slide are read from their shapes (`src/office/slides.ts`: name plus `ISK_MODEL` tags,
  else the presentation mirror), each slide is checked in its own engine session, findings read "Slide n · …" and go to
  their slide and shape (PowerPointApi 1.5).
- **Number all parts** (2026-11-26, round 4): right of the compatibility check the top bar shows a button with the
  renumber pictogram while a part of the page has no reference numeral (the engine's page commands `pageActions`, no
  selection needed; `uxlogic.pageMenus`; the engine gives the pictogram as `choiceBarIcon`). On a page without parts, or
  once every part is numbered, there is no button (context-only). The button opens the menu "Number all parts" with
  *10, 20, 30 …* and *1, 2, 3 …*; a row runs `applyPageAction` (one undo step, live sync redraws the slide). A selected
  numeral offers the same menu. Numbering covers the editor's page; the session does not know the numerals of other
  slides.
- **Option pictograms of the travel modes and phases** (round 4): `travel-walk`, `travel-bike`, `travel-car`,
  `travel-transit`, `travel-none`, `phase-l1`, `phase-l2`, `phase-l3`, `phase-3`, `phase-circuit` are in the table
  shared with the COM add-in (`src/ui/icons.ts`, `test/icons.test.ts` compares both).
- **Compare with the previous slide** (2026-11-25, PowerPoint only): a button in the top bar marks on the selected slide
  what differs from the previous one (engine `exportCompact` of the previous slide, `diff` on the current one): added
  green, changed orange, removed dashed grey, plus a legend; shapes named `ISK_DIFF …`; clicking again removes them.
- **Clean slides …** (2026-11-25, like the COM add-in's Review command): a button in the top bar (next to the
  compatibility check and the comparison) opens a form: *What* – selected elements (only with a selection), current
  slide, all slides; *Charts* – normalise (same proportions, values 0…1), randomise (plausible values, same look) or keep
  the values; *Also* – rename categories, replace texts, remove metadata (on by default) and a random seed (empty = a new
  one; one seed for the whole run, named in the report). The engine's `sanitize` does the work
  (`src/ui/cleanlogic.ts` maps the form; `Session.sanitize`). Selected elements: the editor session (one undo step
  there), the units tracked on the slide are redrawn (also with live sync off). Current slide / all slides
  (PowerPointApi 1.5 with tags): each slide's units are read as they are now (moved or resized units are placed first,
  `slideSession`), cleaned in a temporary session (`cleanSlide`), and only the changed units are redrawn on their slide
  (same unit ids, so the old shapes are replaced; native units go straight to their slide, an SVG picture needs that
  slide shown, which `writeUnits` does and then shows the previous one again). Units the editor holds take the cleaned
  model. The report replaces the form: counts, seed, at most 12 distinct lines and the note that native PowerPoint
  charts and tables, notes, comments and document properties are not changed. **Gaps:** Office.js has no way to make
  the slide changes one undo step (the form says so and suggests cleaning a copy); outside PowerPoint (dev page) and in
  the COM add-in's sidebar (where the COM add-in owns the slide and has its own command) the form offers the selection
  and the editor page only.
- **Export scope** (2026-11-25, maintainer requirement, as in the COM add-in): SVG, PNG and the domain data exports
  always cover the selection – one or several elements, a group counts once – if there is one, otherwise the current
  slide (`src/export.ts`, `resolveExportSource`). The top bar shows the scope before the export buttons ("Export –
  selection (3)" / "Export – slide"), so do the button tooltips and the "Export data" section in Settings. Several units
  selected on the slide are now all loaded into the editor and selected together (`SlideSync.loadSelection`), so the
  editor selection is the slide's selection. Without a selection the current slide's units are read into a temporary
  session (as they are on the slide now) and exported as the whole slide; a slide without InventaSketch elements says
  "Nothing to export on this slide". Outside PowerPoint and in the COM sidebar the editor page is exported ("Export –
  page"). Files are named `inventasketch-selection.*`, `inventasketch-slide-<n>.*` or `inventasketch.*`.
- **Rounded rectangles** take their corner radius as PowerPoint's adjustment (PowerPointApi 1.10, `adjustments.set`).
- Clean slides, the export scope and loading several selected units are covered by unit tests with the same stand-ins
  (`test/cleanslides.test.ts`, `test/exportscope.test.ts`, `test/multiselect.test.ts`); **not yet run in PowerPoint**.
- The all-slides check, the comparison and the corner radius are covered by unit tests against a stand-in of the
  Office.js object model and a stand-in engine (`test/slides.test.ts`); **not yet run in PowerPoint** (needs the dev
  certificate). The tests found that the presentation mirror was never read back (tag keys come back in upper case);
  fixed for the selection too (`mirrorKey`).
- **Resize**: centred parts (gears, bearings, wheels: `centred`) scale about their centre by default, Ctrl from the
  opposite edge; other objects the other way round. A label next to the pointer shows the size (or factor) and the
  active mode with its Ctrl alternative.
- **Choices as dropdowns** (like the COM add-in): every choice is a dropdown, also the engine's action choices of an
  element and of a selected part; see "Interaction concept" below.
- **Quick add** (like the COM add-in): a selected flowchart, UML, ER, BPMN or basic element (`chain`) shows blue
  triangles outside its sides; click adds a connected copy (`quickAdd`), drag and drop adds it at the drop point. The
  context bar then starts with "Make it …", which opens the insert box with what the new element can become
  (`nextItems`, typing searches the library; the pick calls `replaceItem`). No thumbnail row is appended to the bar.
- **Coupling:** moves, resizes and parameter edits keep gears in mesh and gears on their shafts (engine `Coupling`);
  holding Alt while releasing edits freely (`couple: false`, `Session.couple`).
- **Anchor** (settings, on by default, like the COM add-in's ribbon toggle): a line end dragged onto a snap target
  attaches to it and follows when the target moves. Off: the end still snaps but stays where it is.
- **Pie menu "Label ▸"** for lines, arrows, dimensions and lead lines: entries generated from the type parameters
  (text prompts, switches, choices, text size), like the COM add-in.

## UI/UX round 2026-11-24 (parity with the COM add-in)

Follows the binding UX rules in the roadmap ("Plan 2026-11-24"). Pure rules in `src/ui/uxlogic.ts` and
`src/ui/insertbox.ts`, unit-tested in `test/uxround.test.ts`.

- **Context-only bar:** since 2026-11-25 the main action plus up to three pictograms plus "⋯" (see "Interaction
  concept" below). Mirror and rotate appear only when `transformEffect` says they change the drawing (a circle or a gear
  in axial view shows none of them); the pie menu follows the same rule. Pictograms with bilingual tooltips; the bar
  never grows with content.
- **One insert flow:** the insert button in the bar, "Insert …" in the pie menu and Ctrl+Space (also without a
  selection) open the insert box at the pointer. Without typing it lists the parts that fit the selection first
  (marked "fits"/"passt") and then the recent items; typing searches the whole library (`search`). ↑/↓ move, Enter
  takes the marked row, Esc or a click elsewhere closes. Rows show the library thumbnails. The chosen item follows the
  pointer with snapping (click places it, Esc cancels). Recent items (last 12) are kept in the per-user settings
  (localStorage); library inserts count too.
- **Multi-selection bar:** with two or more elements selected (a group counts as one), the bar shows the operations of
  `arrangeOptions` as icons with tooltips – one view for all (the mechanism kept), centres on a row or column, even
  spacing, like the first, renumber reference numerals – each only when it changes something; a click runs `arrange`
  (one undo step). Style and the pie menu stay available.
- **Select assembly:** shown when the selection is coupled with parts that are not selected yet (`assembly`); a click
  selects all coupled objects, which then get the multi-selection bar.
- **Snap labels:** while dragging, the label from `snapMove` ("axis", "pitch circle", "pin 2") is shown next to the
  snap target (docking point, snapped circle or segment).
- **Draw the path:** a link of a self-built linkage with F = 1 (`trace` returns a path) offers "Draw the path"; it
  inserts the coupler curve of the link's end as a motion path (`kin.path`, or `kin.path.closed` for a closed curve;
  an open path without arrowhead), one undo step (`drawTrace`).
- **Motion mode:** see "Motion mode" below (since 2026-11-25; before that COM-only).

  free build port (`buildPorts`): 15 px beyond the port along its outward direction with a thin dashed lead line,

  corner, so the element can still be dragged by its centre (same as the COM add-in). The tooltip names what docks
  there. The context bar keeps clear of the "+" and the rotate handle. A click opens the insert box at the "+" with the
  parts that dock there (`buildItems`, marked "fits"); choosing one docks it, coupled and selected (`buildPlace`, one
  undo step). Typing searches the whole library; anything that does not dock there starts the normal placement at the
  pointer.
- **Stretch a shaft end:** dragging the "+" at a shaft end (`stretch`) previews the new end on the shaft axis (pointer
  snapped, then projected onto the axis) with the change in length next to the pointer; on release `buildStretch`
  lengthens or shortens the shaft without coupling, so the parts on it keep their place (one undo step).
- **Live coupling preview:** while dragging or resizing the selection, the neighbours the coupling will move or scale
  on release (meshing gears, parts on a shaft) are drawn in blue (`couplingPreview` with `dx`/`dy`, or `sx`/`sy` about
  the resize pivot), throttled to about 15 updates per second with a trailing update for the last position. Release,
  Esc or Alt (free edit) clears it. Rotations have no preview.
- **Ghost positions:** a link of a self-built linkage with F = 1 (`dof`, or a traced path) gets a bar button (icon
  `cmd-animate`) that inserts four dashed grey copies of the chain over the crank's range as one group (`drawGhosts`,
  one undo step).
- **Dimension between two parts:** with exactly two parts selected, the multi-selection bar shows "Dimension between
  the two (centre distance)" from `arrangeOptions` (`dim`, icon `cmd-dimension`, label from the engine); a click inserts
  an aligned dimension docked on both axes (one undo step).

Checked in the browser (dev.html, 2026-11-24): five "+" on a spur gear (four meshing, one hub), a meshing gear docked
from the right "+"; a shaft lengthened from 120 to 155 mm and shortened by a real mouse drag with the gear on it kept in
place; a bearing docked at the shaft end; a typed search item started the normal placement; the blue preview of the
meshing gear while dragging and while resizing its partner, cleared on release, matching the result; twelve ghost
links inserted as one group; a 70.7 mm centre distance dimension between two gears.

## Interaction concept (2026-11-25, parity with the COM add-in)

Follows [interaction-ux.md](../design/interaction-ux.md) (sections 4–6a) and
[engineering-calculations.md](../design/engineering-calculations.md) section 11. Pure rules in `src/ui/barlogic.ts`,
`src/ui/pielogic.ts`, `src/ui/handlelayout.ts`, `src/ui/partlogic.ts`, `src/ui/valuecard.ts` and `src/ui/tools.ts`
(tests `test/barlogic.test.ts`, `test/pie-layout.test.ts`, `test/handlelayout.test.ts`, `test/partlogic.test.ts`).

- **Floating bar:** the same structure for every element. First the main action with a short label: "Make it …" right
  after a quick add, else "Values" (Explore and Engineer, elements with values), else "Data" (charts), else "Text", else
  "View ▾", else the first pictorial style choice, else "Insert". Then up to three pictograms in the COM order: telling
  type actions whose pictogram is unique (steps keep their label), the view, Insert, sketch / coupler curve / ghost
  positions / explode / move mode / select assembly, the pictorial choices, choices shown by name and menus, rotate 90°
  and mirror where they change the drawing. Then "⋯" (the pie). 32 px buttons; the bar is fully visible within 90 px of
  the pointer and fades out until 420 px (UX review G1). A multi-selection keeps its groups (one view for all | align
  and distribute | select assembly) plus "⋯". A selected part shows its name, its first three commands (choices as
  dropdowns) and "⋯". No cycle buttons and no style button any more (Style ▸ in the pie has "Line and fill …").
- **Choices are dropdowns:** one dropdown per choice: the parameter choices (`inspector`), the line type
  (`conversions`), the line style, the view, and the engine's action choices – every action with the same `choice` is
  an option (element: key `@a.<choice>`, part: `@p.<choice>`). The closed button shows `choiceBarIcon` if set, else the
  current option's name when `choiceLabelInBar`, else the current option's pictogram or its `previewSvg` picture, plus a
  caret; menus (`choiceMenu`) show "Label ▸". The open list shows every option with pictogram or picture and label, the
  current one marked; Esc or a click elsewhere closes it. Picking runs the option (input options ask first); a menu
  option that adds a part ("Fill below ▸") selects the new part, so its own choices are right there.
- **Pie menu:** eight fixed places clockwise from 12 o'clock: Text …, Edit ▸, Insert …, Duplicate, Style ▸, Delete,
  View ▸, Arrange ▸. Edit holds the element's own commands (Values ▸, Label ▸, type actions that no choice covers,
  numeral, menu choices, explode, sketch, move mode, F = n, coupler curve, ghost positions, Parts ▸; with a part
  selected its commands and "Whole element"); Style one entry per state choice ("Line style: Dashed ▸") plus "Line and
  fill …"; View the views; Arrange rotate either way, mirror, order, grouping and "Select connected ▸". A place with
  nothing for the element stays greyed and keeps the menu open on a click; a place with one entry shows it directly
  (Edit, Style and Arrange keep their name). Submenus open by click and start with "← Back"; more than eleven entries
  continue in "More ▸". One label size (11.5 px); labels wrap at spaces into up to three lines inside their sector
  (no-break spaces keep "…" and "▸" with their word); the full label and a one-line hint show below the ring. The centre
  names the element (or its part, or the open submenu) and closes the menu. The ring is moved, and in a narrow pane
  scaled, so it stays inside the pane.
- **Selection halo:** every selected element (one, several, the result of "Select connected") gets a soft blue glow
  along its drawn outline: a copy of its SVG drawing in a layer above the drawing, through an SVG filter (alpha widened
  by 3.5 px, blurred by 4 px, tinted, the element itself cut out). It lies under every handle, shows over elements that
  lie on top of the selected one, and is hidden while dragging. A selected part glows in full, its element fainter. The
  dashed member boxes of a multi-selection are gone.
- **Select connected:** Arrange ▸ "Select connected ▸" lists the kinds that apply (`connectOptions`: net, moves along,
  following elements, closed loop, room walls) with the number of elements and a one-line hint; hovering an entry shows
  what it would add with a fainter glow, choosing it selects them. Ctrl+double-click on an element selects the most
  meaningful kind (`connected` with mode `auto`).
- **Parts:** a click on a chart's curve, point, axis … selects that part at once, also when the chart was not selected
  yet (`partAt`); Del deletes the part (`part.delete`) or hides it, never the element; a deleted point leaves its curve
  selected.
- **Values:** in Explore and Engineer the bar starts with "Values" (pictogram x=) for elements with values
  (`hasValues`); Edit ▸ Values ▸ lists every value at every level. The value card (right of the element) has one row per
  value: marker (✎ entered, = derived, ○ default, ⇄ linked, ⚠ in conflict), symbol, name, field (the engine's parser:
  "4k7", "230 V", "1,5 kW"), unit and × for an entered value; under derived values the formula step by step (`explain`,
  Explore and Engineer; Engineer adds the source and a fourth digit); a status line (✓, what is missing, conflict) and
  each conflict with both values; a refused entry shows its message under its row. Enter or leaving the field stores
  the value (`setValue`, one undo step), × clears it (`clearValue`). Below: "Calculator …" and "Show values on the
  drawing" (`showValues`). The level (Quick sketch, Explore, Engineer) is a document setting (`setValueLevel`), in
  Settings and in the card.
- **Calculator and code import** (top bar): the calculator with units (`calc`, an optional target unit through
  `convertUnit`; "230 V * 16 A", "1500 rpm in rad/s"); the code import takes pasted or opened matplotlib, pgfplots or
  TikZ code (`importCode`: read, never run) and reports what was imported and what not. `.py` and `.tex` files chosen in
  the import button open it too.
- **Handle layout:** one layout for the handles of the selected element (`src/ui/handlelayout.ts`, a port of the COM
  `HandleLayout`, pure screen geometry): the frame handles, the rotate handle, point diamonds, quick-add triangles and
  value grips stay; every build "+" takes the first free place around its preferred place (15 px beyond its port, a
  hub's beyond the top right corner), further out and leaning up to 40°, with a gap of 3 px; a "+" that had to move
  keeps a dashed lead to its port.
- **Grips on values** (charts): the `dragHandles` of the selected element as blue-rimmed squares with arrowheads in the
  allowed direction; the point grips of a curve show with the selected curve or point. Dragging shows where the value
  lands and its label beside the pointer (`moveHandle` with `preview`, about 15 times a second); release is one undo
  step, Esc cancels, a click selects the grip's part.

Checked with unit tests, the type check and the production build; **not yet checked in a browser or in PowerPoint**.
The gaps of this round are closed in "Handles on the drawing" below.

## Handles on the drawing (2026-11-26, parity with the COM add-in)

Pure rules in `src/ui/handlelogic.ts` (tests `test/handlelogic.test.ts`); the engine methods are in
`src/InventaSketch.Engine/EngineWeb.cs` (tests `WebHandleApiTests`) plus `insertHandles`/`applyInsertHandle`.

- **Progressive disclosure** (COM `Reveal`): right after a selection only the frame, the point diamonds, the grips of a
  selected part and the one primary "+" show – a line's free end, a gear's right side, else a meshing side, a connection
  port, a free axis end, any port; diagram nodes the quick-add triangle below. Every other handle (more "+", insert dots,
  lock badges, corner dots, branch handles, grips, the other triangles) fades in as the pointer comes near (fully within
  24 px, gone beyond 56 px, also near its anchor); Shift shows all. Faded-out handles take no clicks.
- **One layout for all handles:** "+" (priority 90), insert dots (50, optional), lock badges (70, may orbit their contact
  point), corner dots (40, optional, slide along their segment) and branch handles (30, optional, orbit) are placed by
  `resolveHandles` around the fixed frame handles, point diamonds, triangles and grips. Elements smaller than 24 px and
  segments shorter than 28 px get no corner dots or branch handles.
- **Lock badges** (only while "Anchor" is on, like the COM toggle): every place where the element touches another and
  follows it (meshing gears, a part on a shaft, concentric parts, belts, docked line ends; engine `links`) shows a tiny
  dot on the contact point and a padlock badge beside it – closed: coupled, open and lighter: released; blue with its lead
  under the pointer, the tooltip says what it is and what a click does. A click releases or couples it (`toggleLink`,
  one undo step).
- **Corner dots and branch handles** on wires, pipes, roads and polylines (`polylineHandles`): a click on the hollow dot
  adds a corner where the dot is drawn, dragging bends the line there in one go (snapped and docked; `insertCorner`, one
  undo step, branches stay docked). A double-click on a corner removes it (`removeCorner`). The branch handle beside the
  dot draws a new line of the same kind from the line: drag it to a pin or anywhere (Shift: 15° steps), a click adds a
  15 mm stub (`branch`, the branch selected). Dropping an end of a line on a free end of a line of the same kind joins both
  (`joinLines`, one undo step). A click on a point diamond without moving no longer stores (or snaps) the point.
- **Insert dots** between the rows and columns of a table (`insertHandles`): small "+" right on the line, the tooltip
  names the row or column; a click inserts there (`applyInsertHandle`, one undo step).
- **Dragging a whole curve:** pressing on the selected curve of a chart drags the curve (its `byPart` grip moves by the
  pointer's offset, the dashed outline shows where it lands, the value label beside the pointer); release moves its data
  (`moveHandle`, one undo step), a click without moving selects the part under the pointer. Point grips are small circles;
  grips that do not belong to the selected part fade in near the pointer.
- **Value card:** in Explore a ↔ grip beside every positive value: drag left or right and the value changes by a factor e
  per 90 px (three significant digits) while every value that depends on it follows in the card (`dragValue` with
  `preview`); release stores it (one undo step), Esc restores. A value with tolerances shows its range under its row
  ("Range: 180 V … 220 V", `values` `range`). The ⚠ badge (amber triangle just outside the top right corner) marks a
  selected element whose entered values conflict (Explore and Engineer); a click opens its value card.
- **Calculation sheet …** (value card footer and Edit ▸ Values ▸): the sheet of the element (`calcSheet`) as CSV,
  Markdown or LaTeX with copy (clipboard, else the text is selected for Ctrl+C) and download
  (`inventasketch-calculation.csv|md|tex`); **Insert as table** adds it as an annotation table (`ann.table`) right of the
  element, or below it when there is no room (`insertCalcTable`, one undo step, the table selected).
- **Sketched curves** send the pointer time (ms since the press) with every trail point (`sketchCurve` `[x, y, t]`), so the
  drawing speed hint works as in the COM add-in.

Checked with unit tests (engine and TypeScript), the type check and the production build; **not yet checked in a
browser or in PowerPoint**. Still different from the COM add-in: an unfilled closed shape keeps a faint glow inside its
outline; the value level is a setting of the engine document (COM: a presentation tag) and `importCompact` does not
carry it from a slide model. Junction icons, the "+" at free line ends and the corner selection followed on 2026-11-26
(next section).

## Medium colours, names across slides, checks and line ends (2026-11-26, parity with the COM add-in)

Follows [interaction-ux.md](../design/interaction-ux.md) section 6b and
[engineering-calculations.md](../design/engineering-calculations.md) section 10.11. Pure rules in
`src/office/designations.ts` and `src/ui/handlelogic.ts` (tests `test/medium-names.test.ts`); the additive engine
methods `lineEnds`, `extendLine`, `crossings`, `connectCrossing`, `insertMediumLegend` and `valueSettings` are in
`src/InventaSketch.Engine/EngineWeb.cs` (tests `WebDrawOnApiTests`).

- **Colour by medium:** Settings ▸ "Colour by medium" ▸ Off (own colours) / By medium (`setColorBy`, one undo step).
  Every object counts as changed, so live sync redraws every unit the task pane tracks; the colours come from the engine
  at render time, so Off restores the original look. Like black and white, the slide model brings the mode into the
  page session (`importCompact`). **Insert legend** (same place) lists the colours used: in PowerPoint those of every
  unit on the shown slide (read into a temporary session, `mediumColours` mode `used`), else those of the editor page;
  the engine builds the legend (`insertMediumLegend`, the COM add-in's `LineMedia.Legend`: title, a short line and the
  name with its standard per colour) as one group top right, and in PowerPoint it is written onto the slide as a unit.
  Nothing coloured yet: a short note, nothing inserted. Conductor, line role and fluid stay dropdowns from the engine's
  action list (`line.role`), as do "Designation …", "Value label …", "End markers" and the elements' "Designation …"
  (`line.ref`, `line.value`, `line.ref.ends`, `elem.ref`).
- **Designations across slides:** when the task pane opens and when another slide is shown (the Office selection
  handler checks the shown slide), the units of every slide are read (`readSlideUnits`), each other slide's designations
  come from the engine (`designations` in a temporary session per slide) and the map "designation → slide numbers" goes
  to the editor session (`setContinuations`, pages called slides). Units drawn from the task pane then carry the
  continuation marker "→ W3, slide 4" at the free end nearest the slide edge. "Select connected ▸ Same name" is one of
  the engine's kinds (`connectOptions` offers it when another element on the page has the name); for a designation that
  also occurs on other slides the submenu adds "Same name: also on slides 2, 4" (an entry that only informs, as in the
  COM add-in), and "Select connected ▸" shows for it even when nothing on the page shares the name. **Limits:** Office.js
  has to read every slide's shapes and tags for the map, so it is read on these two occasions only, not after every edit
  (a designation typed on another slide counts from the next slide change); units drawn before keep their markers until
  they are drawn again (as in COM); the task pane's own page picture (the editor state's SVG) shows no markers, because
  the engine's `StateOf` renders the page without the session's continuations (draw plans have them). Outside PowerPoint
  (dev page, COM sidebar) there is no map.
- **Checks in the value card:** below the values and conflicts the card lists the element's plausibility findings
  (`checks`): "⚠ message (rule) [source]" for warnings, "ⓘ …" for hints, each with **Mute** (`muteCheck`, one undo step;
  undo brings it back). The ⚠ badge on the drawing now also shows for a warning (Explore and Engineer; tooltip "Plausibility
  warning"). **Show values in** (a fold-out in the card) sets the preferred unit per quantity kind for the drawing:
  pressure bar/MPa/kPa, speed of rotation min⁻¹/rev/s/rad/s, energy kWh/MJ/J, power W/kW, or automatic
  (`setUnitPreference`, one undo step; the current ones from `valueSettings`). The engine knows no unit "s⁻¹" for a speed
  of rotation, so the web add-in offers rev/s (the COM add-in's ribbon offers "s⁻¹", which the engine refuses). Muted
  checks and preferred units are settings of the engine document (saved with it and with every unit drawn from it);
  `importCompact` does not carry them from a slide model, so they last for the task pane session (COM: presentation
  tags `ISK_MUTED`, `ISK_UNITS`).
- **Junction icons:** a selected wire or pipe shows a small ring with a cross and a dot beside each crossing with another
  line that hops at crossings (`crossings`; layout priority 60, fades in near the pointer); a click connects the line
  there: it is split and both parts dock onto the other line, which draws the junction dot (`connectCrossing`, one undo
  step, the line stays selected). In PowerPoint only lines loaded into the task pane take part.
- **"+" at free line ends:** every free end of a line that can be drawn on and has no line end port "+" (polylines,
  roads, rails, straight lines and arrows …; `lineEnds`) shows the same blue "+" 18 px beyond the end (the end of the line
  is the primary handle when no port "+" is). Drag it: the line runs to where it is released (snapped and docked like a
  line end; Shift 15° steps). Click it: drawing goes on, every click adds a corner, a click on the last corner
  (double-click), Enter, Esc or a right-click ends; the corners placed are committed at once (`extendLine`, one undo
  step; a straight line or arrow becomes a polyline). The preview is the engine's drawing of the extended line
  (`extendLine` with `preview`, about 15 times a second). The line end port "+" of cables, pipes and ducts keeps its
  click (the insert box with what fits there) and draws the line on when dragged.
- **Corner selection:** a click on a corner of a line with free corners (without moving it) selects it (orange); the bar
  shows "Corner n", **Split the line here** (a closed outline: **Open the outline here**; `splitLine`) and **Remove this
  corner** (`removeCorner`) where the engine allows them; a second click deselects, any edit ends the selection.

Checked with unit tests (engine and TypeScript), the type check and the production build; **not yet checked in a
browser or in PowerPoint**.

## Motion mode (2026-11-25)

Like the COM add-in ("Moving gear trains live by dragging in motion mode", linkage dragging): dragging moves things only
the way they can move. Pure rules in `src/ui/motionlogic.ts`, unit-tested in `test/motionlogic.test.ts`.

- **Toggle:** the bar shows "Move: drag turns the gears / linkage" (icon `cmd-motion`, a toggle button with
  `aria-pressed`) between the build commands and "Explode" when `motionInfo` says `linkage`, or `gear` with `coupled`
  true. A lone gear coupled with nothing only spins in place, which shows nothing, so it gets no button (same rule as
  COM). The state is session only, like COM: it is not saved and the task pane always starts in edit mode. Switching it
  on shows a short hint in the status line.
- **Handles in motion mode:** a selected part that can move shows only what moves it: a gear its dashed frame and a
  cross at its centre, a link its joints (filled blue). Resize, rotate, quick-add and build "+" handles are hidden, so
  every drag on it is a motion. Parts that cannot move keep their usual handles and drag as usual.
- **Turning a gear:** dragging anywhere on the selected gear's frame (or on any coupled gear, which gets selected) turns
  it about its centre (`x`/`y` from `motionInfo`) by the angle the pointer sweeps around it, accumulated across ±180° and
  full circles (clockwise on screen positive); Shift turns in 15° steps. The angle is shown at the centre with a dashed
  lever to the pointer.
- **Dragging a link:** dragging a joint handle of the selected link pulls that joint; dragging elsewhere on a link pulls
  its nearest joint. The pulled point and a dashed line from its start are shown.
- **Preview and release:** during the drag the engine's `motionPreview` (the turned train or the moved chain) is drawn
  in the ghost layer at about 15 updates per second (same throttle as the coupling preview, trailing update for the last
  position) and the current drawing of the moved objects is dimmed; the context bar hides once the drag moves. Release
  applies `motionTurn` or `motionDrag` once (one undo step: "Turn" / "Move linkage"); a click without a drag changes
  nothing; Esc cancels and restores the bar. With motion mode off dragging edits as before.

Checked in the browser (dev.html, 2026-11-25): a spur gear with a meshing gear docked from its build "+": the motion
button appears (not for a lone gear), a real mouse drag over a quarter circle turned the gear by +90.4° and its mate
from -10° to -100.4° with both centres unchanged, one undo step "Turn"; with motion mode off the same drag moved the
gear. An exploded `kin.fourbar` (F = 1): dragging the crank's joint by 30° about its pivot kept all link lengths
(9.124 / 27.371 / 22.809 mm) with the pivots in place, one undo step "Move linkage"; the preview showed the moved crank
and coupler with their originals dimmed; a drag started on the coupler with nothing selected selected it, and Esc
cancelled it without a change. Known gap (engine): `motionPreview` leaves out a link that only moves through a docked
joint (the rocker of the four-bar), and every preview solves from the document state rather than from the last
preview, so a long drag of a linkage may jump to the other assembly mode in the preview (the COM add-in solves from
the last position).

## Webspace package

`dist/InventaSketch-Webspace` (and `dist/InventaSketch-Webspace-<version>.zip`, which contains the folder) offers the web
add-in from any HTTPS webspace, without a server on the user's computer. Build it with `scripts/package-webspace.ps1`
(Windows) or `scripts/package-webspace.sh` (Linux/macOS); `scripts/build.ps1` and `scripts/build.sh` run it after the web
and COM packages and only warn if the web build is missing. The work is done by `hosts/office-web/webspace/package.mjs`
(`npm run webspace`).

Contents:

- the built web add-in (`hosts/office-web/dist` without `dev.html`, source maps and the localhost manifest), including the
  precompressed engine files (`_framework/*.br`, `*.gz`);
- `index.html` with `setup.js`: the setup page. It takes the folder of its own address (`location`, without file name,
  query and fragment) as the add-in address, checks it with the rules of `create-manifest.ps1` (HTTPS only, no query or
  special characters), shows it and offers the manifest as `manifest-<host>[-<port>].xml` on a button. It also explains
  "Upload My Add-in" for PowerPoint on Windows, Mac and the web, the Mac `wef` folder and the Windows registry
  (`HKCU\Software\Microsoft\Office\16.0\WEF\Developer`) with copyable commands for when the upload is missing, the shared
  folder catalog and central deployment by IT. Texts are German if the browser language starts with `de`, otherwise
  English; a button switches the language;
- `manifest-template.js`, generated from `scripts/manifest.mjs` (`manifestTemplateModule`): the manifest template and
  `fillManifest`, so the page and `node scripts/manifest.mjs <url>` produce the same XML for the same address
  (`test/webspace.test.ts`);
- `.htaccess` (Apache) and `web.config` (IIS): MIME types for `.wasm`, `.dll`, `.dat`, `.blat`, `.json`, `.js`, `.br`,
  `.gz`; no directory listing; `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, `Cache-Control: no-cache` (a new
  upload arrives at once); crawlers, preview services and tools are rejected by user agent. Apache serves the `.br`/`.gz`
  copies with `Content-Encoding` when the browser accepts them (needs `mod_rewrite` and `mod_headers`, otherwise the
  originals are served). IIS serves the originals and compresses itself; precompressed files would need the optional URL
  Rewrite module, whose absence breaks the whole folder;
- `robots.txt` (`Disallow: /`; crawlers only read it at the root of a host, in a subfolder the header and the robots meta
  tag apply);
- `version.json` (version line on the page) and `downloads.json` with `downloads/`: the other editions found next to the
  package in `dist`: `InventaSketch-AddIn-<version>.zip` (COM add-in) and `InventaSketch-LibreOffice-<version>[-<rid>].oxt`.
  Only existing files are listed, never expected ones; without them the page says that there are no other editions.

Use: upload the folder with all files (FTP programs show `.htaccess` only with hidden files enabled) to a folder with a
name that cannot be guessed, e.g. `https://example.com/isk-7k2q9x/`. Requirements: HTTPS with a valid certificate and no
password protection (Office add-ins cannot sign in). Open the address in the browser, download the manifest and upload it
in PowerPoint (Home > Add-ins > More Add-ins > My Add-ins > Upload My Add-in). Presentation data is not sent to the
webspace. Updates: upload the new folder and replace the old content; a new manifest is only needed when the manifest
changed.

Origin: setup page, server settings and packaging were ported from Slidemax-Webspace (same copyright holder) and
translated to English.

Verified 2026-11-20 on Windows: package build (111 files, COM add-in ZIP listed); the folder served by a local static
server in a subfolder over HTTPS (temporary self-signed certificate) and HTTP; the page loaded in headless Edge in German
and English: address `https://localhost:<port>/isk-test`, generated manifest well-formed XML with this address and
identical to `scripts/manifest.mjs`; over HTTP the page refuses the address and disables the button. Not yet verified:
`.htaccess` on a real Apache and `web.config` on IIS, loading the add-in in PowerPoint from a webspace.
